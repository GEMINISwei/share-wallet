## 兩種錢包

| | 一般錢包 | 旅遊錢包 |
|---|---|---|
| 本質 | 一份**資產**，有餘額 | **分帳**，算誰欠誰 |
| 用途 | 家用、個人帳戶、共同存款 | 一趟旅程 |
| 交易 | 收入、支出、轉帳、代墊、還款、調整餘額 | 誰付了多少、哪些人分攤 |
| 生命週期 | 持續使用 | 進行中 → 結算中 → 已結帳（封存） |

**兩種錢包之間不互通**：不能互相轉帳，也不連動。出遊的花費一律在旅遊錢包處理，
旅遊錢包的結帳只是紀錄，協助大家把帳理清楚，不會寫回任何一般錢包。

### 刪除錢包

- **管理者隨時可以刪除錢包**，不論一般錢包的餘額與代墊未還、旅遊錢包在哪個狀態（含封存）。
- 刪除是**永久的**：成員、分類、帳目與異動紀錄一起刪掉，無法復原。畫面要輸入錢包名稱才能確認。

**為什麼不設條件**：錢包是一群彼此信任的人自己的帳，要不要留由他們決定，系統不替他們判斷
「餘額不是 0 就不能刪」。這類條件只會逼使用者先記一筆調整把餘額歸零再刪，多一步卻沒有保護到什麼；
真正的保護是刪除前的確認。

## 成員與權限

錢包的角色只有兩級，是**錢包成員紀錄上的欄位**，與全站的角色權限（管理後台用的那套）無關，
不會新增或指派全站角色。

| | 管理者 | 成員 |
|---|---|---|
| 查看錢包與帳目 | ✓ | ✓ |
| 記帳 | ✓ | ✓ |
| 修改、刪除**自己**記的帳 | ✓ | ✓ |
| 修改、刪除**別人**記的帳 | ✓ | |
| 產生、撤銷邀請連結 | ✓ | |
| 把成員升為管理者、把管理者降為成員、移除成員 | ✓ | |
| 修改錢包設定（名稱、分類等） | ✓ | |
| 刪除錢包 | ✓ | |
| 離開錢包 | ✓ | ✓ |
| 旅遊錢包：開始、取消結算 | ✓ | |

- 建立錢包的人是管理者。錢包建立時只有他一人。
- 透過邀請加入的人一律是**成員**，由管理者升為管理者。
- 一個錢包可以有多位管理者。管理者可以把其他管理者（或自己）降為成員。
- 錢包**至少要有一位管理者**：最後一位管理者不能離開、不能被降為成員，要先把別人升為管理者。
- 只看得到**自己加入的錢包**；不是成員的人打開錢包的網址，看到的是「錢包不存在」。

### 不設全站權限

- 使用錢包**不需要任何全站權限**：每個登入的人都有完整的錢包功能，「一般用戶」角色的權限與錢包無關。
- 超級管理者多的只有：在**後台的錢包管理頁**（`/admin/wallets`）新增、查看、編輯、刪除**所有**錢包，
  看餘額與明細。使用者區裡超級管理者也只看到自己加入的錢包。
- 超級管理者對任何錢包的操作**等同錢包管理者**（設定、分類、成員升降與移除、改刪任何帳、刪除錢包），
  異動紀錄會記下是超級管理者改的。
- 超級管理者在後台新增錢包時**指定一位啟用中的使用者當管理者**（可以是自己）；指定別人時自己不成為成員。
  超級管理者也可以像一般使用者一樣在使用者區建立自己的錢包。
- 後台的錢包列表依名稱、類型篩選，顯示管理者、成員數、餘額與建立時間；錢包的設定、成員、分類與刪除
  在後台有對應的頁面，規則與使用者區相同。

**為什麼不設全站權限**：錢包裡誰能做什麼已經由錢包自己的管理者／成員決定，再疊一層全站權限，
只會多出「全站沒有權限、錢包裡卻是管理者」這種沒有意義的組合。超級管理者需要的是救援與管理的入口，
所以放在後台，不混進使用者自己的錢包清單。

**為什麼至少一位管理者**：沒有管理者的錢包沒有人能邀請、移除成員或修改設定，
而且沒有任何一般使用者能把它救回來，只剩超級管理者能從後台介入。

### 離開與移除

- 成員可以自己離開；管理者可以移除其他成員。
- 離開或被移除時**只刪掉成員紀錄**，他記過的帳原樣保留，記帳人照樣顯示他的暱稱。
- 之後透過邀請連結可以再加入，回來時是成員。
- 旅遊錢包另有限制，見[成員異動](#成員異動)。

**為什麼只刪成員紀錄**：帳目上的記帳人指向的是使用者帳號而不是成員紀錄，
所以成員離開不會讓帳目失去記帳人。保留一筆「已離開」的成員紀錄只會讓名單、權限判斷
都要多處理一種狀態，卻沒有實際用途。

**為什麼只有兩級**：共用一份資產或一趟旅程的通常是彼此信任的少數人，需要區分的只有
「能不能管人和改別人的帳」。多一級擁有者只會多出轉移擁有權、擁有者離開怎麼辦這類規則，
卻沒有對應的實際需求。

### 紀錄

- 每一筆帳都記錄**記帳人**。「自己記的帳」看的是記帳人的帳號：離開後再透過邀請加入的人，
  照樣能修改、刪除自己以前記的帳。
- 帳目的新增、修改、刪除都留下**異動紀錄**：誰、什麼時候、改前與改後。
  **只記帳目**，錢包設定、成員、分類的變更不記。異動紀錄不能修改或刪除。
- **所有成員都看得到**異動紀錄：帳目詳情裡看這一筆的歷史；錢包頁的「異動紀錄」列出整個錢包的紀錄，
  包含已經刪除的帳。
- 超級管理者**靠超管身分**做的操作會標記「超級管理者」：他不是這個錢包的成員，
  或他改刪的是別人的帳而他在錢包裡不是管理者。超級管理者以成員身分記自己的帳不標記。

**為什麼成員都看得到**：帳目本來就是所有成員一起看的，異動紀錄只是同一份帳的歷史；
只給管理者看，成員就無從發現自己的帳被別人改過。

**為什麼不記設定、成員、分類**：要對帳的是錢，錢包名稱或分類名稱改了不影響任何金額。
分類改名也不會讓舊的異動紀錄跟著變，紀錄裡存的是當時的分類名稱。

## 邀請與註冊

### 邀請連結

- 管理者產生邀請連結，傳給要加入的人。
- 有效期限**一天**，期限內**不限人數**。
- 每個錢包**同時只有一條**有效的連結。管理者可以隨時撤銷，或重新產生（舊連結隨即失效）。
- 有效期內管理者回到成員頁**還看得到同一條連結**，可以再複製；過期之後就像沒有連結，要重新產生。
- 連結**只有管理者看得到**（含超級管理者），一般成員看不到也不能轉傳現有的連結。
- 入口在成員頁標題列的「邀請」按鈕，點開的對話框裡產生、複製、重新產生、撤銷。
- 已結帳（封存）的旅遊錢包不能產生邀請連結，也不能透過舊連結加入。
  結算狀態在旅遊錢包的功能才加入，這條規則跟著那時一起實作。

**為什麼連結看得到第二次**：連結一天就過期，而且只能讓人以成員身分加入；
若只在產生當下顯示一次，管理者想再傳給別人時只能重新產生，之前傳出去的反而跟著失效。

### 加入流程

打開邀請連結後，三種情況**最後都停在同一個確認頁**（「加入 XXX 錢包？」），
按下確認才加入。已登入的人也要確認，不會直接加入。

| 狀況 | 流程 |
|---|---|
| 已登入 | 確認頁 |
| 有帳號、未登入 | `/login?invite=…` → 登入 → 確認頁 |
| 沒有帳號 | `/signup?invite=…` → 註冊 → 確認頁 |

`invite` 參數只帶邀請 token，登入或註冊後由系統依 token 組出確認頁的網址，
**不接受任意的導向網址**，避免被拿來做 open redirect。不是 token 格式的 `invite` 直接忽略，
登入後照常回首頁。

- 連結的網址是 `/invite/<token>`。沒登入的人打開時導到 `/login?invite=<token>`，
  登入頁的「註冊」連結與註冊頁的「登入」連結都帶著同一個 `invite`。
- 確認頁是跟登入、註冊頁同一種單張卡片（沒有側欄），顯示錢包的**名稱、類型、成員數**，
  旅遊錢包另外顯示目的地與日期。取消回到錢包列表。
- **已經是成員**的人打開連結：確認頁改成「你已經是這個錢包的成員」，附前往錢包的連結，
  沒有確認按鈕；角色不變（管理者不會因此變成成員）。
- 連結**過期、被撤銷或錢包已刪除**（包含登入、註冊完才發現）：顯示錯誤頁「連結無效或已過期，
  請向管理者要新的連結」，附前往錢包列表的連結。三種情況不分開說明，不透露錢包是否還存在。
- 離開或被移除的人可以用有效的連結再加入，回來時是成員。
- 有人加入時通知管理者見[通知](#通知)，推播的功能才實作。

### 註冊

| 路徑 | 用途 |
|---|---|
| `make db superuser` | 超級管理者**只能**用 CLI 建立，網頁上沒有初始化畫面 |
| `/signup` | 一般使用者註冊，**任何人都可以註冊**，註冊完直接登入 |

- 一般使用者註冊後自動綁上 seed 建立的「一般用戶」系統角色（權限一開始是空的，超管可在後台調整；
  不能改名、不能停用），看不到管理後台，只看得到自己加入或建立的錢包。
- 沒有邀請的使用者註冊後可以自己建立錢包，再邀請別人。

**為什麼不做網頁初始化**：那種畫面在部署之後、有人完成之前是公開的，誰先進站誰就拿到全部權限。

## 一般錢包

### 餘額

- 建立時可以填**初始餘額**（預設 0）。
- 餘額**可以是負的**（例如用來記信用卡）。
- 餘額是**存起來的值**，每次記帳、修改、刪除時當下就更新，
  不是顯示時才從明細加總。
- 可以**調整餘額**：輸入實際餘額，系統把差額（實際餘額 − 目前餘額）記成一筆「調整」交易。
  差額是 0 時擋下（餘額沒有變化），不留一筆 0 的帳。
- 調整**可以刪除、不能修改**：刪除就是反向套用那筆差額。之後修改或刪除更早的帳，
  不會回頭重算調整的差額。調錯了就刪掉重新調整。

**為什麼調整不能改**：調整的意思是「在那個當下，實際餘額是多少」。事後修改要重新問一次
「以哪個時間點的餘額為準」，答案會隨其他帳的修改而變；存成固定差額，刪掉重調就清楚。

| 操作 | 餘額 | 代墊未還金額 |
|---|---|---|
| 收入 | ＋金額 | |
| 支出 | −金額 | |
| 轉帳 | 轉出方 −、轉入方 ＋ | |
| 代墊 | −金額 | ＋金額 |
| 還款 | ＋金額 | −金額 |
| 調整餘額 | 設為輸入的值 | |
| 修改某一筆 | 套用新舊差額 | 套用新舊差額 |
| 刪除某一筆 | 反向套用 | 反向套用 |

### 帳目列表

- **錢包頁就是帳目**：餘額、帳目列表，以及成員、分類、異動紀錄、設定的入口。
- 列表依**日期新到舊**，同一天的依記帳時間新到舊；一次載入一部分，往下「載入更多」。
- 「記一筆」（收入或支出）與「調整餘額」放在頁面標題列，手機收在 ⋮ 選單裡。
- 點某一筆帳打開詳情：看欄位、記帳人與這一筆的異動紀錄，有權限時可以修改、刪除。

### 收入與支出

- 欄位：金額、分類、日期、備註。日期只有日期、不含時間，預設今天，可以填過去或未來；
  備註選填，最多 200 字。
- 修改時可以在收入與支出之間切換，分類要跟著換成對應類型的。
- 分類被封存之後，修改用過它的帳時**可以保留原本的分類**，但不能改選其他已封存的分類。
- **不做分攤**：一般錢包是一份資產，錢從錢包出去就是錢包的支出。

**為什麼不分攤**：一般錢包代表的是一筆實際存在的錢，錢從錢包付出去就是錢包的支出，
沒有「誰該負擔多少」的問題。需要算誰欠誰的情境用旅遊錢包；錢包替某個人付的錢用代墊記錄。

### 轉帳

- 從一個一般錢包轉到另一個一般錢包，兩邊各產生一筆，**一起建立、一起修改、一起刪除**。
- 操作的人必須**同時是兩個錢包的成員**。
- 任兩個一般錢包之間都可以轉，金額原樣搬過去，**不換匯**（見[金額](#金額)）。
- 轉帳不算收入或支出。

### 代墊與還款

代墊的意思是**錢包幫某人墊付了多少**，不是「錢包欠誰」。

- **代墊**：輸入替誰代墊、金額，**餘額立刻扣掉**。
- **還款**：輸入這個人還了多少，**餘額加回同樣金額**。
- 還款是對「人」而不是對某一筆代墊，可以分多次還。
- **還款不可超過**這個人目前未還的金額。
- 已經部分還款的代墊，改小金額後若會讓未還金額變負，**不允許修改**。
- 代墊對象**不需要是成員**，自由輸入名字。系統依名字（去掉前後空白）歸成同一個對象，
  輸入時提示這個錢包用過的名字。
- 每個對象的未還金額也是**存起來的值**，與餘額一起更新。
- 代墊與還款**不算收支統計，也不選分類**。欄位：對象、金額、日期、備註。

錢包頁面顯示目前代墊未還的清單，例如「小明 500、小華 1,200」。

### 分類

- 每個分類都帶**類型**（收入或支出），建立後不能改；記收入只能選收入分類，記支出只能選支出分類。
- 每個一般錢包有自己的分類，建立時附一組預設分類，名稱依建立者的語系寫入，之後就是一般文字：

  | 類型 | 預設分類 |
  |---|---|
  | 收入 | 薪資、獎金、投資、其他 |
  | 支出 | 餐飲、交通、購物、居家、娛樂、醫療、其他 |

- 管理者可以新增、改名、刪除分類。同一個錢包裡，同類型的分類名稱不能重複（去掉前後空白後比對，大小寫視為不同）。
- **刪除分類是封存**：封存的分類不再出現在分類管理與記帳的選單裡，用過它的帳照樣顯示原本的名稱。
  名稱不能重複只看還沒封存的分類，所以封存之後可以再建一個同名的分類。

**為什麼刪除是封存**：分類被帳目引用著，真的刪掉，舊帳就會失去分類或得跟著改。
封存讓管理者照樣能整理選單，舊帳也不會變。
- 轉帳、代墊、還款、調整不選分類。

## 旅遊錢包

### 建立

- 欄位：名稱、目的地、起訖日（結束日不可早於開始日）。
- 一個旅遊錢包代表**一趟旅程**，只結算一次。下一趟旅程建新的錢包。

### 記帳

- 欄位：金額、付款人、分攤對象、分攤方式、日期、備註。**不選分類**。
- 付款人與分攤對象**一定要是這個錢包的成員或管理者**。
- **沒有公費**：每一筆都是「某人先付，指定的人分攤」。

**為什麼不選分類**：旅遊錢包要回答的是誰付了、誰該分攤，分類對結算沒有作用，
多一個欄位只會讓旅途中記帳變慢。所以分類只屬於一般錢包。

### 分攤

- **均分**：除不盡的零頭依序分給前幾人，**付款人優先**。
  例如 100 由 3 人均分、付款人在其中：付款人 34，其他兩人各 33。
- **指定金額**：每人金額不同，**加總必須剛好等於總額**，否則不能送出。

### 結算流程

```text
進行中 ──開始結算──▶ 結算中 ──全部確認還款──▶ 已結帳（封存）
   ▲                    │
   └──────取消結算───────┘
```

1. **進行中**：正常記帳，隨時可以查看每人目前的淨額。
2. **開始結算**（管理者）：帳目**鎖住**，不能新增、修改、刪除。
   系統依每人淨額算出**最少轉帳次數**的清償方案，例如「A 付 B 1,200」「C 付 B 300」。
3. **還款**：清償方案的每一筆分別處理。
   - 付款人可以標記「我已付款」，但不能自己確認完成。
   - **收款人或管理者**確認收款，記錄是誰確認的。
4. **已結帳**：清償方案**每一筆都確認收款後**自動進入。錢包封存，**只能查看**。

**取消結算**（管理者）：回到進行中，帳目解鎖，**已確認的還款紀錄全部作廢**。
修改帳目後重新開始結算，會重新計算清償方案。

**為什麼只結算一次**：一個旅遊錢包對應一趟旅程，旅程結束就該把帳清乾淨。
只結算一次，狀態就只有進行中、結算中、已結帳三種，不必處理「哪些帳已經結過、哪些還沒」。
下一趟旅程開新錢包，帳目也不會混在一起。

### 成員異動

- 在這個錢包裡**有任何付款或分攤紀錄**的成員，不能離開也不能被移除。
- 沒有紀錄的成員可以自由離開或被移除。

## 金額

- 金額**一律是整數**，兩種錢包都一樣。
- 金額**大於 0**；只有調整餘額記下的差額可以是負的。
- 金額與餘額的上限是 2⁵³ − 1（瀏覽器能精確表示的最大整數），記帳會讓餘額超過時擋下。
- **不設幣別**。錢包需要標示是哪一種錢時寫在名稱裡，例如「日本旅遊（日圓）」。
- 錢包列表顯示**所有一般錢包餘額的總和**。旅遊錢包沒有餘額，不算在內。

**為什麼用整數**：日常記帳與分帳都以整數金額進行，用整數可以避免小數的進位誤差，
分攤時也只需要處理整數的零頭。

**為什麼不設幣別**：系統不做換匯，幣別只會是一個標籤。一旦有了這個標籤，就得回答
同幣別才能轉帳嗎、改了幣別既有的轉帳怎麼辦、不同幣別的總和怎麼顯示，而這些規則都沒有實際需求。
用到多種貨幣的使用者自己知道哪些錢包是同一種錢，寫在名稱裡就夠了。

## 通知

以推播通知，原則是只推「要你做點什麼」或「與你直接相關」的事。**一般記帳不推播**。

| 事件 | 通知對象 |
|---|---|
| 旅遊錢包開始結算 | 所有成員，內容是自己要付給誰、或誰會付給自己 |
| 旅遊錢包取消結算 | 所有成員 |
| 付款人標記「我已付款」 | 收款人 |
| 收款被確認 | 付款人 |
| 結帳完成、錢包封存 | 所有成員 |
| 自己記的帳被別人修改或刪除 | 原記帳人 |
| 有人透過邀請連結加入 | 該錢包的管理者 |
| 被升為管理者、被移出錢包 | 當事人 |

iPhone 必須把網站加到主畫面才收得到推播，這是 iOS 的限制。

## 介面

- **以手機為主**，畫面以行動裝置設計，桌機版只要能用。
- 以 PWA 安裝到主畫面（manifest 已經有了）。
- **不做即時同步**：別人記的帳不會自動出現在畫面上。
- 要支援**下拉重新整理**。iOS 加到主畫面的 PWA 沒有瀏覽器內建的下拉重新整理，要自己實作。
