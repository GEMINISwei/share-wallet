## 兩種錢包

| | 一般錢包 | 旅遊錢包 |
|---|---|---|
| 本質 | 一份**資產**，有餘額 | **分帳**，算誰欠誰 |
| 用途 | 家用、個人帳戶、共同存款 | 一趟旅程 |
| 交易 | 收入、支出、轉帳、代墊、還款、調整餘額 | 誰付了多少、哪些人分攤 |
| 生命週期 | 持續使用 | 進行中 → 結算中 → 已結帳（封存） |

**兩種錢包之間不互通**：不能互相轉帳，也不連動。出遊的花費一律在旅遊錢包處理，
旅遊錢包的結帳只是紀錄，協助大家把帳理清楚，不會寫回任何一般錢包。

### 錢包列表

- 列表分成「一般」「旅遊」兩個分頁，預設是一般。從錢包頁回到列表時，停在那個錢包所屬的分頁。
- 「一般」分頁最上方顯示所有一般錢包餘額的總和（見[金額](#金額)），手機上放大置中；「旅遊」分頁不顯示。
- 分頁是膠囊形的切換，每個錢包是一張卡片。
- 每個人可以把錢包設為**最愛**，在錢包頁的選單裡設定、取消；列表上的最愛只顯示星號，不能從列表切換。
- 最愛是**自己的標記**，記在自己的成員紀錄上，別的成員看不到也不受影響。
  只有成員能設最愛：超級管理者打開沒加入的錢包時沒有這個選項。已結帳的錢包也能設。
- 每個分頁裡最愛的排在前面，其餘維持加入的先後；**已結帳的一律排在最後**，最愛也一樣。

**為什麼分兩個分頁**：兩種錢包要看的數字不一樣（餘額與淨額），旅遊錢包又會隨著一趟趟旅程越積越多，
混在一起時常用的一般錢包會被擠到下面。

**為什麼已結帳的最愛也排最後**：已結帳的錢包只能查看，排在進行中的錢包前面只會擋路；
星號留著，要回頭看時還是找得到。

### 刪除錢包

- **管理者隨時可以刪除錢包**，不論一般錢包的餘額與代墊未還、旅遊錢包在哪個狀態（含封存）。
- 刪除是**永久的**：成員、分類、帳目與異動紀錄一起刪掉，無法復原。畫面要輸入錢包名稱才能確認。

**為什麼不設條件**：錢包是一群彼此信任的人自己的帳，要不要留由他們決定，系統不替他們判斷
「餘額不是 0 就不能刪」。這類條件只會逼使用者先記一筆調整把餘額歸零再刪，多一步卻沒有保護到什麼；
真正的保護是刪除前的確認。

## 成員與權限

錢包的角色只有兩級，是**錢包成員紀錄上的欄位**，與全站的角色權限（管理後台用的那套）無關，
不會新增或指派全站角色。

| | 管理者 | 成員 |
|---|---|---|
| 查看錢包與帳目 | ✓ | ✓ |
| 記帳 | ✓ | ✓ |
| 修改、刪除**自己**記的帳 | ✓ | ✓ |
| 修改、刪除**別人**記的帳 | ✓ | |
| 產生、撤銷邀請連結 | ✓ | |
| 把成員升為管理者、把管理者降為成員、移除成員 | ✓ | |
| 修改錢包設定（名稱、分類等） | ✓ | |
| 刪除錢包 | ✓ | |
| 離開錢包 | ✓ | ✓ |
| 旅遊錢包：開始、取消結算 | ✓ | |

- 建立錢包的人是管理者。錢包建立時只有他一人。
- 透過邀請加入的人一律是**成員**，由管理者升為管理者。
- 一個錢包可以有多位管理者。管理者可以把其他管理者（或自己）降為成員。
- 錢包**至少要有一位管理者**：最後一位管理者不能離開、不能被降為成員，要先把別人升為管理者。
- 只看得到**自己加入的錢包**；不是成員的人打開錢包的網址，看到的是「錢包不存在」。

### 不設全站權限

- 使用錢包**不需要任何全站權限**：每個登入的人都有完整的錢包功能，「一般用戶」角色的權限與錢包無關。
- 超級管理者多的只有：在**後台的錢包管理頁**（`/admin/wallets`）新增、查看、編輯、刪除**所有**錢包，
  看餘額與明細。使用者區裡超級管理者也只看到自己加入的錢包。
- 超級管理者對任何錢包的操作**等同錢包管理者**（設定、分類、成員升降與移除、改刪任何帳、刪除錢包），
  異動紀錄會記下是超級管理者改的。
- 超級管理者在後台新增錢包時**指定一位啟用中的使用者當管理者**（可以是自己）；指定別人時自己不成為成員。
  超級管理者也可以像一般使用者一樣在使用者區建立自己的錢包。
- 後台的錢包列表依名稱、類型篩選，顯示管理者、成員數、餘額與建立時間；錢包的設定、成員、分類與刪除
  在後台有對應的頁面，規則與使用者區相同。

**為什麼不設全站權限**：錢包裡誰能做什麼已經由錢包自己的管理者／成員決定，再疊一層全站權限，
只會多出「全站沒有權限、錢包裡卻是管理者」這種沒有意義的組合。超級管理者需要的是救援與管理的入口，
所以放在後台，不混進使用者自己的錢包清單。

**為什麼至少一位管理者**：沒有管理者的錢包沒有人能邀請、移除成員或修改設定，
而且沒有任何一般使用者能把它救回來，只剩超級管理者能從後台介入。

### 離開與移除

- 成員可以自己離開；管理者可以移除其他成員。
- 離開或被移除時**只刪掉成員紀錄**，他記過的帳原樣保留，記帳人照樣顯示他的暱稱。
- 之後透過邀請連結可以再加入，回來時是成員。
- 旅遊錢包另有限制，見[成員異動](#成員異動)。

**為什麼只刪成員紀錄**：帳目上的記帳人指向的是使用者帳號而不是成員紀錄，
所以成員離開不會讓帳目失去記帳人。保留一筆「已離開」的成員紀錄只會讓名單、權限判斷
都要多處理一種狀態，卻沒有實際用途。

**為什麼只有兩級**：共用一份資產或一趟旅程的通常是彼此信任的少數人，需要區分的只有
「能不能管人和改別人的帳」。多一級擁有者只會多出轉移擁有權、擁有者離開怎麼辦這類規則，
卻沒有對應的實際需求。

### 紀錄

- 每一筆帳都記錄**記帳人**。「自己記的帳」看的是記帳人的帳號：離開後再透過邀請加入的人，
  照樣能修改、刪除自己以前記的帳。
- 帳目的新增、修改、刪除都留下**異動紀錄**：誰、什麼時候、改前與改後。
  **只記帳目**，錢包設定、成員、分類的變更不記。異動紀錄不能修改或刪除。
- **所有成員都看得到**異動紀錄：帳目詳情裡看這一筆的歷史；錢包頁的「異動紀錄」列出整個錢包的紀錄，
  包含已經刪除的帳。
- 超級管理者**靠超管身分**做的操作會標記「超級管理者」：他不是這個錢包的成員，
  或他改刪的是別人的帳而他在錢包裡不是管理者。超級管理者以成員身分記自己的帳不標記。

**為什麼成員都看得到**：帳目本來就是所有成員一起看的，異動紀錄只是同一份帳的歷史；
只給管理者看，成員就無從發現自己的帳被別人改過。

**為什麼不記設定、成員、分類**：要對帳的是錢，錢包名稱或分類名稱改了不影響任何金額。
分類改名也不會讓舊的異動紀錄跟著變，紀錄裡存的是當時的分類名稱。

## 邀請與註冊

### 邀請連結

- 管理者產生邀請連結，傳給要加入的人。
- 有效期限**一天**，期限內**不限人數**。
- 每個錢包**同時只有一條**有效的連結。管理者可以隨時撤銷，或重新產生（舊連結隨即失效）。
- 有效期內管理者回到成員頁**還看得到同一條連結**，可以再複製；過期之後就像沒有連結，要重新產生。
- 連結**只有管理者看得到**（含超級管理者），一般成員看不到也不能轉傳現有的連結。
- 入口在成員頁標題列的「邀請」按鈕，點開的對話框裡產生、複製、重新產生、撤銷。
- 已結帳（封存）的旅遊錢包不能產生邀請連結，也不能透過舊連結加入，打開舊連結看到的是「連結無效」。

**為什麼連結看得到第二次**：連結一天就過期，而且只能讓人以成員身分加入；
若只在產生當下顯示一次，管理者想再傳給別人時只能重新產生，之前傳出去的反而跟著失效。

### 加入流程

打開邀請連結後，三種情況**最後都停在同一個確認頁**（「加入 XXX 錢包？」），
按下確認才加入。已登入的人也要確認，不會直接加入。

| 狀況 | 流程 |
|---|---|
| 已登入 | 確認頁 |
| 有帳號、未登入 | `/login?invite=…` → 登入 → 確認頁 |
| 沒有帳號 | `/signup?invite=…` → 註冊 → 確認頁 |

`invite` 參數只帶邀請 token，登入或註冊後由系統依 token 組出確認頁的網址，
**不接受任意的導向網址**，避免被拿來做 open redirect。不是 token 格式的 `invite` 直接忽略，
登入後照常回首頁。

- 連結的網址是 `/invite/<token>`。沒登入的人打開時導到 `/login?invite=<token>`，
  登入頁的「註冊」連結與註冊頁的「登入」連結都帶著同一個 `invite`。
- 確認頁是跟登入、註冊頁同一種單張卡片（沒有側欄），顯示錢包的**名稱、類型、成員數**，
  旅遊錢包另外顯示目的地與日期。取消回到錢包列表。
- **已經是成員**的人打開連結：確認頁改成「你已經是這個錢包的成員」，附前往錢包的連結，
  沒有確認按鈕；角色不變（管理者不會因此變成成員）。
- 連結**過期、被撤銷或錢包已刪除**（包含登入、註冊完才發現）：顯示錯誤頁「連結無效或已過期，
  請向管理者要新的連結」，附前往錢包列表的連結。三種情況不分開說明，不透露錢包是否還存在。
- 離開或被移除的人可以用有效的連結再加入，回來時是成員。
- 有人加入時通知管理者見[通知](#通知)，推播的功能才實作。

### 註冊

| 路徑 | 用途 |
|---|---|
| `make db superuser` | 超級管理者**只能**用 CLI 建立，網頁上沒有初始化畫面 |
| `/signup` | 一般使用者註冊，**任何人都可以註冊**，註冊完直接登入 |

- 一般使用者註冊後自動綁上 seed 建立的「一般用戶」系統角色（權限一開始是空的，超管可在後台調整；
  不能改名、不能停用），看不到管理後台，只看得到自己加入或建立的錢包。
- 沒有邀請的使用者註冊後可以自己建立錢包，再邀請別人。

**為什麼不做網頁初始化**：那種畫面在部署之後、有人完成之前是公開的，誰先進站誰就拿到全部權限。

## 一般錢包

### 餘額

- 建立時可以填**初始餘額**（預設 0）。
- 餘額**可以是負的**（例如用來記信用卡）。
- 餘額是**存起來的值**，每次記帳、修改、刪除時當下就更新，
  不是顯示時才從明細加總。
- 可以**調整餘額**：輸入實際餘額，系統把差額（實際餘額 − 目前餘額）記成一筆「調整」交易。
  差額是 0 時擋下（餘額沒有變化），不留一筆 0 的帳。
- 調整**可以刪除、不能修改**：刪除就是反向套用那筆差額。之後修改或刪除更早的帳，
  不會回頭重算調整的差額。調錯了就刪掉重新調整。

**為什麼調整不能改**：調整的意思是「在那個當下，實際餘額是多少」。事後修改要重新問一次
「以哪個時間點的餘額為準」，答案會隨其他帳的修改而變；存成固定差額，刪掉重調就清楚。

| 操作 | 餘額 | 代墊未還金額 |
|---|---|---|
| 收入 | ＋金額 | |
| 支出 | −金額 | |
| 轉帳 | 轉出方 −、轉入方 ＋ | |
| 代墊 | −金額 | ＋金額 |
| 還款 | ＋金額 | −金額 |
| 調整餘額 | 設為輸入的值 | |
| 修改某一筆 | 套用新舊差額 | 套用新舊差額 |
| 刪除某一筆 | 反向套用 | 反向套用 |

### 帳目列表

- **錢包頁就是帳目**：最上方是餘額，下面是帳目列表；其他功能的入口見[錢包頁的版面](#錢包頁的版面)。
- 列表依**日期新到舊**，同一天的依記帳時間新到舊；一次載入一部分，往下「載入更多」。
- 「記一筆」（收入、支出、轉帳或代墊）與「調整餘額」放在頁面標題列；手機的位置見[錢包頁的版面](#錢包頁的版面)。
- 列表**依日期分組**，每組的標題是日期，今天、昨天寫成「今天」「昨天」。
- 每一筆的標題優先用**備註**；沒有備註時是分類（轉帳、代墊等沒有分類的，用原本的標題，例如「轉出至 存款」）。
  標題旁邊用膠囊外框標出**分類**，沒有分類的標出類型（轉帳、代墊、還款、調整餘額），跟標題一樣時不重複標。
  備註佔走標題時，轉帳的對方錢包、代墊的對象改寫在下一行，跟記帳人放在一起。
- 金額的正負一眼要分得出來：增加的帶「+」並用綠色，減少的用紅色。
- 點某一筆帳打開詳情：看欄位、記帳人與這一筆的異動紀錄，有權限時可以修改、刪除。

### 收入與支出

- 欄位：金額、分類、日期、備註。日期只有日期、不含時間，預設今天，可以填過去或未來；
  備註選填，最多 200 字。
- 修改時可以在收入與支出之間切換，分類要跟著換成對應類型的。
- 分類被封存之後，修改用過它的帳時**可以保留原本的分類**，但不能改選其他已封存的分類。
- **不做分攤**：一般錢包是一份資產，錢從錢包出去就是錢包的支出。

**為什麼不分攤**：一般錢包代表的是一筆實際存在的錢，錢從錢包付出去就是錢包的支出，
沒有「誰該負擔多少」的問題。需要算誰欠誰的情境用旅遊錢包；錢包替某個人付的錢用代墊記錄。

### 轉帳

- 從一個一般錢包轉到另一個一般錢包，兩邊各產生一筆（轉出、轉入），**一起建立、一起修改、一起刪除**。
- 在「記一筆」裡選類型「轉出」或「轉入」，再選對方錢包；選單列出自己加入的其他一般錢包。
  欄位：金額、對方錢包、日期、備註，**不選分類**。
- 建立的人必須**同時是兩個錢包的成員**（超級管理者也一樣，沒加入的錢包不能轉）。
- 任兩個一般錢包之間都可以轉，金額原樣搬過去，**不換匯**（見[金額](#金額)）。
- 轉帳不算收入或支出。
- 帳目顯示「轉出至 X」「轉入自 Y」，對方錢包的名稱兩邊的成員都看得到。
- 修改**只能改金額、日期、備註**，不能換對方錢包，也不能在轉帳與收支、轉出與轉入之間切換；
  轉錯錢包就刪掉重記。
- 修改、刪除要**在兩個錢包都有權限**：自己記的，要兩邊都還是成員（或超級管理者）；
  別人記的，要兩邊都是管理者（或超級管理者）。記帳人離開其中一個錢包後就不能改刪，再加入後可以。
- 兩邊各自留異動紀錄，紀錄裡存的是當時的對方錢包名稱。
- 其中一個錢包被刪除時，另一邊那一筆**保留、餘額不變**，顯示「已刪除的錢包」；
  之後**只能刪除、不能修改**，刪除時照這個錢包自己的權限，只反向套用這一邊。

**為什麼兩邊都要有權限**：一筆轉帳會改兩個錢包的餘額，只在其中一邊有權限就能改，
另一邊的成員會發現自己的帳被一個沒加入他們錢包的人改了。

**為什麼不能換錢包**：換錢包等於從一個錢包撤掉、在另一個錢包新增，權限與異動紀錄都要跨三個錢包判斷；
刪掉重記一樣清楚，兩邊的紀錄也各自完整。

**為什麼錢包刪除時另一邊保留**：別人刪掉自己的錢包，不該讓這個錢包的餘額跟著變。

### 代墊與還款

代墊的意思是**錢包幫某人墊付了多少**，不是「錢包欠誰」。

- **代墊**：在「記一筆」選類型「代墊」，輸入替誰代墊、金額，備註寫代墊了什麼。**餘額立刻扣掉**。
- **還款是對某一筆代墊**：打開那筆代墊的詳情按「還款」，只輸入金額、日期、備註，
  **餘額加回同樣金額**。同一筆代墊可以分多次還。
- 每筆代墊有自己的**未還金額**（代墊金額 − 已還），每個對象的未還金額是他各筆代墊未還的總和。
  兩者都是**存起來的值**，與餘額一起更新。
- **未還金額永遠不能是負的**，新增、修改、刪除都照這條檢查：
  - 還款不可超過那筆代墊目前的未還金額；修改還款時上限是「未還 + 這筆原本的金額」。
  - 代墊改小金額時，不能小於已還的金額。
  - **已經有還款的代墊不能刪除**，要先刪掉它的還款。
- 代墊與還款都**不能改對象**，只能改金額、日期、備註；還款也不能換到另一筆代墊。對象打錯就刪掉重記。
- 代墊對象**不需要是成員**，自由輸入名字。系統依名字（去掉前後空白，大小寫視為不同）歸成同一個對象，
  輸入時提示這個錢包用過的名字。
- 還款是帳目列表裡**獨立的一筆**（「小明 還款」），有自己的記帳人與異動紀錄，
  改刪權限照一般的帳：自己記的，或管理者。代墊的詳情列出它的每一筆還款。
- 任何成員都可以替任何一筆代墊記還款，不限代墊的記帳人。
- 代墊與還款**不算收支統計，也不選分類**。

錢包頁面顯示目前代墊未還的清單，例如「小明 500、小華 1,200」，只列未還大於 0 的人；
清單只是顯示，還款一律從代墊的詳情操作。

**為什麼還款對某一筆代墊**：代墊的備註記的是墊了什麼，還款對著那一筆，就看得出哪一件還清了、
哪一件還沒；對人的總額再從各筆加總得到。

**為什麼不能改對象**：改對象等於把未還金額從一個人搬到另一個人，兩邊都要重新檢查不能變負，
而還款也得跟著搬。刪掉重記一樣清楚，異動紀錄也各自完整。

**為什麼有還款的代墊不能刪**：刪掉代墊卻留著還款，還款就沒有對象；連同還款一起刪，
又會一次改掉別人記的帳。先刪還款再刪代墊，每一步都照各自的權限與紀錄。

### 分類

- 每個分類都帶**類型**（收入或支出），建立後不能改；記收入只能選收入分類，記支出只能選支出分類。
- 每個一般錢包有自己的分類，建立時附一組預設分類，名稱依建立者的語系寫入，之後就是一般文字：

  | 類型 | 預設分類 |
  |---|---|
  | 收入 | 薪資、獎金、投資、其他 |
  | 支出 | 餐飲、交通、購物、居家、娛樂、醫療、其他 |

- 管理者可以新增、改名、刪除分類。同一個錢包裡，同類型的分類名稱不能重複（去掉前後空白後比對，大小寫視為不同）。
- **刪除分類是封存**：封存的分類不再出現在分類管理與記帳的選單裡，用過它的帳照樣顯示原本的名稱。
  名稱不能重複只看還沒封存的分類，所以封存之後可以再建一個同名的分類。

**為什麼刪除是封存**：分類被帳目引用著，真的刪掉，舊帳就會失去分類或得跟著改。
封存讓管理者照樣能整理選單，舊帳也不會變。
- 轉帳、代墊、還款、調整不選分類。

## 旅遊錢包

### 建立

- 欄位：名稱、目的地、起訖日（結束日不可早於開始日）。
- 一個旅遊錢包代表**一趟旅程**，只結算一次。下一趟旅程建新的錢包。

### 記帳

- 欄位：金額、付款人、分攤對象、分攤方式、日期、備註。**不選分類**。
  金額、日期與備註的規則同一般錢包的[收入與支出](#收入與支出)。
- 付款人與分攤對象**一定要是這個錢包的成員或管理者**。付款人預設是自己。
- **沒有公費**：每一筆都是「某人先付，指定的人分攤」。
- 修改、刪除的權限同一般錢包（自己記的帳，或管理者改任何人的），所有欄位都可以改。
  新增、修改、刪除都留下[異動紀錄](#紀錄)，紀錄裡存當時的付款人與每人分攤的金額。
- 錢包頁顯示**每人的淨額**（他付的總額 − 他分攤的總額）：正的是應收、負的是應付，
  所有成員都列出，沒有紀錄的是 0；手機收在選單裡，見[錢包頁的版面](#錢包頁的版面)。下面是帳目列表，排序與「載入更多」同一般錢包的[帳目列表](#帳目列表)。

**為什麼不選分類**：旅遊錢包要回答的是誰付了、誰該分攤，分類對結算沒有作用，
多一個欄位只會讓旅途中記帳變慢。所以分類只屬於一般錢包。

### 分攤

- **均分**：勾選分攤對象（預設全部成員）。除不盡的零頭依序分給前幾人，**付款人優先**，
  其餘的人照**加入錢包的順序**；付款人不在分攤對象裡時，全部照加入順序。
  例如 100 由 3 人均分、付款人在其中：付款人 34，其他兩人各 33。
  金額少於人數時，排在後面的人分到 0。
- **指定金額**：列成一張表，按「新增」加一列，選人、填金額。每一列的金額**大於 0**，
  同一個人不能出現兩次；這一筆不用出錢的人就不加進表裡。**加總必須剛好等於總額**，否則不能送出。

**為什麼零頭照加入順序**：勾選的順序沒有存下來，之後修改那一筆時就重現不出同樣的結果；
加入順序是固定的，同樣的金額與對象每次都分得一樣。

### 結算流程

```text
進行中 ──開始結算──▶ 結算中 ──全部確認還款──▶ 已結帳（封存）
   ▲                    │
   └──────取消結算───────┘
```

1. **進行中**：正常記帳，隨時可以查看每人目前的淨額。進行中不顯示清償方案。
2. **開始結算**（管理者）：帳目**鎖住**，不能新增、修改、刪除。
   系統把每一筆帳加總成每人的淨額，算出清償方案，例如「A 付 B 1,200」「C 付 B 300」。
   方案**只在開始結算時算一次**並存下來，結算中不會變。
   大家的淨額都是 0 時，方案是空的，**直接進入已結帳**；確認框會先說明。
   **一筆帳都沒有時不能開始結算**（不顯示「開始結算」，後端也擋）。
3. **還款**：清償方案的每一筆分別處理。
   - 付款人可以標記「我已付款」，還沒被確認前可以撤回。付款人**不能自己確認**，就算他是管理者也一樣。
   - **收款人或管理者**確認收款，記錄是誰、什麼時候確認的。不必等付款人先標記，當面付現金的可以直接確認。
   - 確認之後，確認的人或管理者可以**撤銷確認**，回到未確認（「我已付款」的標記保留）。
4. **已結帳**：清償方案**每一筆都確認收款後**自動進入，最後一筆的確認因此撤不回。錢包封存，**只能查看**。

**取消結算**（管理者）：回到進行中，帳目解鎖，清償方案連同付款、確認的紀錄**全部作廢**。
修改帳目後重新開始結算，會重新計算清償方案。只有結算中可以取消，已結帳的不能回頭。

**為什麼沒有帳不能結算**：沒有帳的錢包一結算就直接封存，之後再也不能記帳；
這幾乎都是誤按，而已結帳回不了頭，所以從源頭不讓它發生。

- 錢包頁在結算中與已結帳時顯示清償方案，跟自己有關的排在最前面；淨額照樣顯示，不扣掉已確認的部分。
- 結算中照樣可以邀請、加入成員，也可以修改錢包名稱、目的地與日期：新成員的淨額是 0，
  這些欄位也不影響金額。
- 開始、取消結算與標記付款、確認收款**不寫進異動紀錄**（異動紀錄只記帳目），
  每一筆轉帳自己記著誰在什麼時候付款、確認。取消結算後這些紀錄跟著作廢。
- 錢包列表上的旅遊錢包標示「結算中」「已結帳」，已結帳的排在最後（見[錢包列表](#錢包列表)）。

**清償方案怎麼算**：先把應付與應收**金額剛好相同**的一對配成一筆，剩下的每次讓應付最多的人付給
應收最多的人，付到其中一方歸零為止；金額相同時照加入錢包的順序。每個人最後都剛好歸零，
轉帳**最多是有帳的人數 − 1 筆**，同樣的帳每次都算出同樣的方案。

**為什麼不追求真正最少的筆數**：要算出真正最少，得嘗試所有分組方式，計算量隨人數翻倍，
人一多就算不完，只能限制旅遊錢包的人數。這個算法偶爾比最少多一筆，換來的是人數不設上限、
規則只有一種。

**為什麼只結算一次**：一個旅遊錢包對應一趟旅程，旅程結束就該把帳清乾淨。
只結算一次，狀態就只有進行中、結算中、已結帳三種，不必處理「哪些帳已經結過、哪些還沒」。
下一趟旅程開新錢包，帳目也不會混在一起。

### 封存

已結帳的錢包**只能查看**：不能記帳、改設定、升降或移除成員，也不能產生邀請連結或透過舊連結加入。
還能做的只有兩件事：

- 管理者**刪除錢包**（見[刪除錢包](#刪除錢包)）。
- 成員**離開錢包**，有付款或分攤紀錄的也可以；最後一位管理者照樣不能離開。
  離開的人在淨額與清償方案裡照樣顯示。

**為什麼封存後可以離開**：有紀錄的人在結帳前不能離開，是怕淨額少了一個人；結帳後金額不會再變，
留在名單裡只會讓舊旅程一直佔著自己的錢包列表。

### 成員異動

- 在這個錢包裡**有任何付款或分攤紀錄**的成員，不能離開也不能被移除（已結帳之後見[封存](#封存)）。
- 沒有紀錄的成員可以自由離開或被移除。

## 金額

- 金額**一律是整數**，兩種錢包都一樣。
- 金額**大於 0**；只有調整餘額記下的差額可以是負的。
- 金額與餘額的上限是 2⁵³ − 1（瀏覽器能精確表示的最大整數），記帳會讓餘額超過時擋下。
- **不設幣別**。錢包需要標示是哪一種錢時寫在名稱裡，例如「日本旅遊（日圓）」。
- 錢包列表顯示**所有一般錢包餘額的總和**。旅遊錢包沒有餘額，不算在內。

**為什麼用整數**：日常記帳與分帳都以整數金額進行，用整數可以避免小數的進位誤差，
分攤時也只需要處理整數的零頭。

**為什麼不設幣別**：系統不做換匯，幣別只會是一個標籤。一旦有了這個標籤，就得回答
同幣別才能轉帳嗎、改了幣別既有的轉帳怎麼辦、不同幣別的總和怎麼顯示，而這些規則都沒有實際需求。
用到多種貨幣的使用者自己知道哪些錢包是同一種錢，寫在名稱裡就夠了。

## 通知

以推播通知，原則是只推「要你做點什麼」或「與你直接相關」的事。**一般記帳不推播**。

| 事件 | 通知對象 |
|---|---|
| 旅遊錢包開始結算 | 所有成員，內容是自己要付給誰、或誰會付給自己 |
| 旅遊錢包取消結算 | 所有成員 |
| 付款人標記「我已付款」 | 收款人 |
| 收款被確認 | 付款人 |
| 結帳完成、錢包封存 | 所有成員 |
| 自己記的帳被別人修改或刪除 | 原記帳人 |
| 有人透過邀請連結加入 | 該錢包的管理者 |
| 被升為管理者、被移出錢包 | 當事人 |

iPhone 必須把網站加到主畫面才收得到推播，這是 iOS 的限制。

## 介面

- **以手機為主**，畫面以行動裝置設計，桌機版只要能用。
- 以 PWA 安裝到主畫面（manifest 已經有了）。
- **不做即時同步**：別人記的帳不會自動出現在畫面上。
- 要支援**下拉重新整理**。iOS 加到主畫面的 PWA 沒有瀏覽器內建的下拉重新整理，要自己實作。

### 錢包頁的版面

手機的錢包頁由上而下是：摘要、一排常用操作、帳目列表。標題列左邊是返回的圓鈕，標題置中，右邊不放選單。
桌機維持原本的版面。

- **摘要**：數字放大置中。一般錢包顯示餘額，旅遊錢包顯示**我的淨額**（應收或應付）。
  超級管理者打開沒加入的錢包時沒有淨額。
  使用者區的「記一筆」在底部導覽（見[記一筆的入口](#記一筆的入口)）；後台沒有那顆「＋」，
  「記一筆」放在摘要下方，不能記帳時不顯示。
- **常用操作**：最多三個，加上最後一格「更多」，平分一整列。沒有權限或不適用的不顯示，也不拿別的項目補位：

  | 一般錢包 | 旅遊錢包 |
  |---|---|
  | 調整餘額 | 開始結算／取消結算（管理者） |
  | 代墊未還（都還清時不顯示） | 每人淨額 |
  | 成員 | 成員 |

- **更多**：從底部滑出面板，依序列出其餘的項目，沒有權限的不顯示：

  | 一般錢包 | 旅遊錢包 |
  |---|---|
  | 分類 | 異動紀錄 |
  | 異動紀錄 | 設定 |
  | 設定 | 加入／取消最愛 |
  | 加入／取消最愛 | |

- 代墊未還與每人淨額打開成對話框，內容跟桌機頁面上的清單一樣。
- 旅遊錢包**結算中與已結帳時**，清償方案照樣顯示在帳目上方：那時候要做的就是照方案轉帳、確認收款。

**為什麼常用操作放在外面**：這幾項是記帳以外最常點的，收在選單裡每次都要多點一下，也不容易發現。
標題列不再放 ⋮，因為同樣的操作只放一個入口（「更多」），不會讓人不知道該點哪一個。

**為什麼記一筆不收進選單**：記帳是最常用的操作，收進選單每次都要多點一下。

### 記一筆的入口

手機的使用者區，底部導覽依序是「錢包」「＋」「帳號」，「＋」就是記一筆。桌機在錢包頁的標題列。

- **在錢包頁**（一般或旅遊）點「＋」，直接記到這個錢包。
- **在其他頁**點「＋」，先從底部滑出面板選錢包，選好後進到那個錢包並直接開啟記一筆。
  面板分成一般、旅遊兩組，順序跟錢包列表一樣（最愛在前）。已結帳的旅遊錢包不列；
  結算中的列出但不能選，旁邊寫「結算中，不能記帳」。
- **不能記帳時**（結算中、已結帳，或帳目沒有載入），「＋」變灰但照樣可以點，點了用通知說明原因。
- 後台的底部導覽沒有「＋」：後台是管理用的，超級管理者要記帳時從錢包頁摘要列的「記一筆」。

**為什麼放在底部導覽正中間**：手機單手操作時，底部中間是拇指最容易點到的位置，
而且不論在哪一頁都在同一個地方，不必先找到錢包頁的按鈕。

**為什麼不能記帳時變灰而不是隱藏**：隱藏會讓底部導覽的位置跳動；變灰再說明原因，使用者才知道是錢包的狀態，
不是按鈕壞了。
