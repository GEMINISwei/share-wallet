# 系統功能

模板內建的功能怎麼運作、為什麼這樣設計。要執行的指令與救援步驟在 [`operations.md`](operations.md)，
要加新功能見 [`extending.md`](extending.md)。

## 帳號

| 路徑 | 用途 |
|---|---|
| `make db superuser` | 超級管理者**只能**用 CLI 建立，網頁上沒有初始化畫面 |
| `/signup` | 一般使用者註冊，**任何人都可以註冊**，註冊完直接登入 |
| 後台「使用者管理」 | 超級管理者替別人建立帳號 |

- 超級管理者的第一個、第二個、唯一的超管失聯時的救援都走 `make db superuser`
  （見 [`operations.md`](operations.md#建立超級管理者)）。能建立超管的前提是握有主機的 shell，
  不需要保管任何註冊代碼。
- 註冊的帳號自動綁上「一般用戶」系統角色，看不到管理後台。註冊時無法指定角色，請求內容帶了也不採用。
- 登入頁有前往註冊的按鈕，註冊頁也有回登入的按鈕。

**為什麼不做網頁初始化**：那種畫面在部署之後、有人完成之前是公開的，誰先進站誰就拿到全部權限。

## 角色與權限

系統角色只有兩個，由 seed 建立（有 `code`）：

| | 權限 | 怎麼取得 | 可以調整的 |
|---|---|---|---|
| 超級管理者（`super_admin`） | `*`，涵蓋所有操作與日後新增的權限 | 只能由 `make db superuser` 產生，**不能經由 API 指派** | 無 |
| 一般用戶（`user`） | 一開始是空的 | 註冊時自動綁上 | 權限（超管在角色頁調整） |

- 系統角色不能改名、不能停用：名稱由 seed 同步，畫面上依 `code` 查前端字典；停用了就沒有人註冊得進來，
  或超管本身失效。
- 一般用戶的權限只在第一次建立時由 seed 寫入，之後部署不會把超管調整過的權限蓋回去
  （`RoleTable.seed_insert_only_keys`）。
- 新建的使用者沒指定角色時沒有任何權限。

### 後台只開放給超級管理者

使用者與角色的管理（後台）只有超級管理者進得去：前端的 `admin/layout.tsx` 只看是不是
超級管理者，後端這些端點一律要求 `Permission.ALL`。角色上的權限是給**一般帳號**的業務功能用的，
沒有任何一個權限能打開後台。

一般帳號對自己帳號的操作（改暱稱、改密碼、語系）集中在設定頁，不需要任何權限。

即使是超級管理者也不能做的事：停用自己、停用超級管理者、指派超級管理者角色、把 `*` 放進一般角色
（含一般用戶）、修改超級管理者的權限、改名或停用系統角色。

## Session

### 撤銷

每個使用者在 `users` 資料表有自己的 `auth_version`，token 簽發時帶著當下的值，每個請求都會跟資料庫比對，
對不上就要重新登入。所以撤銷就是把 `auth_version` +1，**不用重啟、也不用改 `.env`**：

| 怎麼觸發 | 作用範圍 |
|---|---|
| 換密碼（管理者重設或自己改）、登出 | **單一使用者**，自動 +1 |
| `make db revoke-sessions`（見 [`operations.md`](operations.md#讓所有人登出)） | **所有人**，每個人各 +1 |

單一使用者的 +1 只影響那一個帳號，其他使用者的 token 照常有效：

- 使用者自己改密碼：其他裝置全部登出，這一台會拿到新 token 繼續用。
- 管理者重設密碼：那個人的所有裝置都登出。
- 登出：這個帳號的**所有裝置**一起登出，不只是按下登出的那一台。token 是無狀態的，只刪
  cookie 的話，已經被複製出去的 token 到期前仍然有效，所以登出走的是同一條撤銷路徑。

全員撤銷只用在緊急情況（帳號被盜、懷疑 token 外流）。撤銷本身只是一條 UPDATE，平常的請求也沒有多一次查詢，
負擔在之後**所有人同時重新登入**：

- 每次登入都要算一次 bcrypt，api 是單一行程，人多時登入會排隊變慢。
- 同一個 IP 的登入 5 分鐘內上限 50 次（見〈[限流](#限流)〉）：同一個 NAT 後面超過 50 人時，
  晚到的要等額度回來才登入得了。

撤銷擋不住金鑰外洩：拿到 `JWT_SECRET_KEY` 的人可以自己簽一張帶任何世代的 token。金鑰外洩時要換掉
`JWT_SECRET_KEY` 本身，舊 token 會跟著全部失效（見 [`operations.md`](operations.md#更換-jwt_secret_key)）。

### 不會續期

沒有 refresh token，也沒有「有在操作就延長」。`EXPIRE_HOURS` 是**登入後多久一定要重新登入**
的硬上限，跟有沒有在用無關 —— 設 8 小時的話，早上九點登入的人下午五點會被導回登入頁。

## 密碼

- 記得舊密碼 → 自己在設定頁改。
- 忘記密碼 → 請超級管理者在後台重設（超級管理者全部失聯時用 `make db superuser` 另建一個）。
  模板沒有 email，所以沒有寄重設連結。

## 限流

登入、註冊與改密碼有次數上限（`shared/http/rate_limit.py`，數字在 `modules/users/router.py`），
每一層都是滑動視窗：

| 操作 | 以什麼計數 | 上限 | 成功後 |
|---|---|---|---|
| 登入 | 用戶端 IP + 帳號 | 5 分鐘 10 次 | 歸零 |
| 登入 | 用戶端 IP | 5 分鐘 50 次 | **不歸零** |
| 註冊 | 用戶端 IP | 1 小時 10 次 | 不歸零 |
| 改密碼 | 使用者 | 5 分鐘 10 次 | 歸零 |

- 只看 IP 會讓同一間辦公室互相影響，只看帳號則可以被拿來鎖定別人，所以登入的第一層用兩者的組合。
- 第一層換個帳號名就是新的額度，擋不住「同一個來源對整份帳號清單各試幾次」，所以另有只看 IP 的
  第二層。它的上限訂得寬，讓同一個 NAT 後面的整間辦公室能正常登入；成功也不歸零，否則用自己的
  帳號登入一次就能把額度洗回來。
- 註冊擋的是大量建立帳號，所以成功的那一次也計數；上限要容得下同一個 NAT 後面的一家人或一群朋友一起註冊。
- 用戶端 IP 取自 `X-Real-IP`，主機那層沒有正確轉送時所有人共用同一份額度（見
  [`operations.md`](operations.md#用戶端-ip-與限流)）。

## 語系

前後端同一個語系：語系存在 `locale` cookie，每個 API 請求都帶 `Accept-Language`，
後端的錯誤訊息跟著 UI 走。字串放哪裡、怎麼加語言見 [`extending.md`](extending.md#語系i18n)。
