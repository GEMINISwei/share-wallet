# 0009. 開放一般使用者註冊，超級管理者仍只能用指令建立

狀態：採用（2026-10-26）

取代：[0002](0002-no-web-signup.md)

## 背景

[0002](0002-no-web-signup.md) 假設帳號數量有限、由超級管理者逐一建立。共用錢包是給家人、朋友一起記帳的產品，
加入錢包靠的是邀請連結：收到連結的人多半還沒有帳號，若要先請超級管理者替他開帳號，邀請就失去意義。

常見的自助註冊會一起做 Email 驗證與防機器人。這個系統沒有寄信的能力，帳號也只存暱稱、帳號與密碼，
被大量註冊時的損失是資料表多出一些空帳號，不會牽涉到別人的錢包。

## 決定

- `/signup` 開放任何人註冊，註冊完直接登入。邀請連結帶著 `invite` 參數走完註冊，最後停在加入錢包的確認頁。
- 註冊的帳號自動綁上系統角色「一般用戶」，請求內容帶了角色也不採用；一般用戶看不到後台。
- 註冊以用戶端 IP 限流，成功的那一次也計數。不做 Email 驗證，也不做防機器人。
- 0002 裡仍然有效的部分不變：超級管理者**只能**用 `make db superuser` 建立，網頁上沒有初始化畫面；
  後台只開放給超級管理者，角色上的權限只用在一般帳號的業務功能，沒有任何權限能打開後台。

## 後果

- 收到邀請連結的人自己就能註冊並加入，不必經過超級管理者。
- 註冊入口是公開的，能防的只有限流：同一個 IP 一小時內的次數有上限，但換 IP 就擋不住。
- 沒有 Email，忘記密碼仍然只能請超級管理者重設。
- 能建立超管的前提仍然是握有主機的 shell，不需要保管註冊代碼。
- 出現大量註冊的濫用、或帳號開始帶有需要保護的個人資料時，要補 Email 驗證或防機器人，並重新檢討這份決定。

現在的行為見 [帳號、角色與密碼](../features/accounts-roles.md)，限流見 [限流](../features/rate-limit.md)。
